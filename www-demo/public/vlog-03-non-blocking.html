Why the server stays responsive

A short note about the non-blocking model used by this webserv demo.

One event loop

webserv uses non-blocking sockets and an event loop to handle several clients without creating one blocking process per connection. Slow clients, CGI scripts, and regular static responses are coordinated through readiness events and timeout checks.

Static response

Files can be served while other connections are still open.

CGI timeout

Long-running scripts are bounded by timeout logic.

Stress checks

The demo should remain available after concurrent requests.
